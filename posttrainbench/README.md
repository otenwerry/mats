# PostTrainBench, second pass

Clean restart of the PTB rollback/resume work (2026-07-04). The first pass lives in
`mats/posttrainbench_old/` and is kept as read-only reference — code there is considered
untrusted until re-derived. The trajectory viewer from the first pass is the one
component we keep using as-is; it now lives at the top level of this directory
(`viewer.py`, helpers in `lib/`).

Layout:
- `viewer.py` — the Flask trajectory viewer (`uv run python posttrainbench/viewer.py`,
  then open http://127.0.0.1:5001). Faithful port of the original, plus two new tabs:
  **Continuations** (one page per `exp_probe_context` probe — a copy of the trajectory
  with the probe's cut point marked and the probe Q&A appended at the bottom) and
  **Visuals → Cost** (billed cost of the probes).
- `reconstruct.py`, `exp_probe_context.py` — the reconstruction/probe tools (below).
- `lib/` — the reconstruction package (`runs`, `stream`, `recon_*`, `prompts`) plus the
  viewer's helpers (`render`, `paths`, `locate`).
- `highlights/` — the stamped RH labels/verdicts the viewer + `runs.reward_hacks()` read.
- Outputs (probes, reconstructions) still land in `mats-local/posttrainbench2/`
  (`runs.OUT_ROOT`); the raw HF mirror stays at `mats-local/posttrainbench/`.

Goal, in order:
1. **Context reconstruction only** (this phase): given a run's trajectory file, rebuild the
   exact message context the agent had at an arbitrary point, scaffold by scaffold.
   Trajectories where this can't be done perfectly get a loud, stored fidelity flag.
   Validation target: a small experiment that resumes an agent with reconstructed context
   and asks it to describe what's in its context.
2. Environment/workspace reconstruction (later).
3. Resample/intervention experiments (later).

Data: `mats-local/posttrainbench/` (read-only mirror of the HF traces dataset).
Harness reference: `supermats/PostTrainBench/` (read-only clone; note version drift —
some saved runs predate the current harness, e.g. timestamp prefixes only in newer runs).

## Data-fidelity survey (2026-07-04)

Every task dir in the local mirror has a trajectory file: `solve_out.txt` and/or `trace.txt`.

**Claude Code runs** (`claude_*`, `claude_non_api_*`; qwen3max uses the same stream format):
- `solve_out.txt` is `--output-format stream-json` JSONL: full assistant messages
  (text + tool_use with complete inputs), full tool results, usage tokens, session id,
  CLI version in the `system:init` event.
- Compaction happened in most runs (1–5 `compact_boundary` events per run). The
  post-compaction context is recorded: exactly one synthetic user message
  (`isSynthetic:true`) carrying the summary the model actually saw. So reconstruction is
  possible on both sides of a compaction.
- Non-API Opus runs (`--effort high`) contain thinking blocks **with signatures** in the
  stream.
- Not in the stream: the initial task prompt (saved by harness as `prompt.txt`, not in
  our mirror, but regenerable from `get_prompt.py`), the CLI system prompt/tool schemas
  (regenerated by the CLI at resume; versions used: 2.1.9 / 2.1.34 / 2.1.76).
- OPEN QUESTION: several runs have multiple `system:init` events under one session id
  (up to 7 for claude, 23 for qwen3max), clustered after the agent declared itself done —
  looks like harness relaunches, but the relaunch prompt text is not echoed in the stream
  and the current `run_task.sh` has no loop. Must be resolved before trusting cuts near
  those boundaries.

**OpenCode runs** (`opencode_*`): part-stream JSONL (`step_start`/`text`/`tool_use`/
`step_finish`) with real ids, timestamps, token usage, full tool inputs+outputs, full
assistant text. Missing: the initial user prompt (CLI arg, not echoed), system prompt,
and — for thinking models (kimi-k2-thinking) — reasoning is absent from the stream.
First pass validated byte-faithful session-store reconstruction + `opencode run --session`
resume for this scaffold.
- Data oddity: `opencode_opencode_kimi-k2.5_10h_run1` and `_run2` contain the SAME task
  ids; run1 has `trace.txt`, run2 has `solve_out.txt`. Probably one run mirrored twice.

**Codex runs** (`codex_non_api_*`): item-stream JSONL (`item.completed` for
reasoning-summary / agent_message / command_execution / file_change). Lossy by
construction:
- `file_change` records only `{path, kind}` — apply_patch diff bodies are NOT saved.
- Reasoning is summaries only (`model_reasoning_summary=detailed`), not raw items.
- No token usage, no system prompt, no session/rollout file archived.
Faithful resume is NOT possible; approximate resume requires synthesizing patch bodies
(e.g. from workspace forensics) and must carry a permanent fidelity flag.

## Fidelity-flag principle

Every reconstructed context gets a stored, queryable record of what was synthesized vs
verbatim (per message), and every downstream result inherits the worst flag of its inputs.

## Tools (2026-07-04)

- `reconstruct.py` (free): `--list` (the 30 RH trajectories), `--report` (parse + viewer
  alignment + cut check for all 30), `--trajectory <run_id> --turn <viewer event idx|first_hack>`
  (build a bundle under `mats-local/posttrainbench2/reconstructions/`). `--turn` is a
  viewer event index; mid-message indices snap down to the message boundary (recorded),
  sidechain/user indices are refused with nearby valid alternatives.
- `exp_probe_context.py` (paid): reconstructs, installs a native session, resumes via
  the scaffold CLI, and asks the model to describe its context. Outputs under
  `mats-local/posttrainbench2/probes/`.

Status: all 30 RH trajectories parse and align with the viewer exactly (claude 1 line =
1 event; opencode expansion rule; codex passthrough incl. item.updated/error lines).
26/30 build at first_hack; 4 refused by design (3 sidechain hacks, 1 user-event index).

Validated by probe (claude scaffold, 2026-07-04):
- pre-compaction cut (humaneval_gemma run2 ev66): model's account of task, files,
  and last action matches the trajectory exactly.
- post-compaction cut (healthbench run2 ev440): model correctly reports being in a
  continued-from-summary session, its earliest visible context is the summary, and it
  separates pre- vs post-compaction file activity.

Resume mechanics facts (Claude Code 2.1.181):
- project dir encoding is now every-non-alphanumeric -> '-' (older versions kept '_').
- `claude --print --resume <sid> "<prompt>"` on a session ending in a tool_result
  injects one isMeta user turn "Continue from where you left off." (+ a minimal
  assistant reply) BEFORE the prompt. Detected and flagged per probe
  (`probe_resume_injected_meta_turns`); must be accounted for in any future
  intervention/resample design.

Probe scope: claude runs supported; opencode needs the opencode CLI + provider auth;
codex refused (lossy data: no rollout, no patch bodies, reasoning summaries only);
qwen3max refused (needs the qwen CLI). Probes leave session files under
`~/.claude/projects/-Users-owenterry-supermats-mats-local-posttrainbench2-probes-*`.
